**PatchIt** scans the apps installed on your Android device and tells you which of
them the [Morphe](https://github.com/MorpheApp/morphe-patcher) patch ecosystem can
actually patch — then hands the right patch *sources* to Morphe Manager so it can
do the work.

It never patches anything itself. It answers *whether*, and *by whom*; Morphe
decides *how*.

---

## What it does

| | |
|---|---|
| 🔍 **Scans what's installed** | Real `PackageManager` enumeration in Kotlin: label, version name and code, `sourceDir`, split APKs, signing-certificate SHA-256, install dates, APK size. |
| ✅ **Checks versions honestly** | Compares your build against every source's declared targets — by `versionCode` first, then exact version name, then a loose match. Verdicts: `supported`, `experimental`, `untested`, `too new`, `too old`, `no patches`. |
| 📶 **Works offline** | Both indexes cached in IndexedDB. A fresh install with no network falls back to a bundled snapshot: **966 packages before the first byte is fetched**. |
| 🔗 **Sets Morphe up** | Hands the covering repositories to Morphe via its real `add-source` deep link. Morphe validates and asks before adding anything. |
| 🎨 **Material You 3** | Wallpaper-derived colour, AMOLED black, monochrome, hairline outlines, tinted dividers. |
| 🩺 **Explains itself** | A 500-entry diagnostics log, including uncaught errors and every registry parse warning. |

## Why it exists

Morphe's official patch set covers **three** packages: YouTube, YouTube Music and
Reddit. Everything else lives in the community index — **222 bundles, ~4,100
patches, 964 packages** collected from public repositories.

Knowing *whether your specific installed build* is covered is the hard part, and
it is where this app earns its keep:

```
YouTube               supported     93 patches    1 source
YouTube (too new)     too new        0 of 93      1 source
Chefkoch              supported      3 patches    1 source
Reddit                too old        0 of 62      4 sources
```

An app can be covered by several sources at once, each supporting a different
version — so verdicts are computed **per source**, and the detail sheet shows
which bundle offers what.

## The Morphe contract

There is **no `morphe://` URI scheme**. A button wired to one would silently do
nothing. Morphe Manager exposes exactly two entry points to other apps, and
PatchIt deliberately uses **one**.

### Adding a patch source — the one hand-off

```
https://morphe.software/add-source?github=owner/repo&name=Display%20Name
```

The detail sheet's primary action is **"Add N sources to Morphe"**. Sources are
offered **even when none of their patches match the installed build** — that case
is exactly when you want them, so you can update or downgrade and carry on. The
sheet says the version doesn't match and gives you the button anyway.

### Batch patching — deliberately not implemented

Morphe also accepts:

```kotlin
action = "app.morphe.manager.action.BATCH_PATCH"
extra  = "packages" to arrayOf("com.google.android.youtube")
```

PatchIt does **not** send it. That is a decision, not an omission:

- `BATCH_PATCH` arms a patch-and-install queue. A scanner that does that from one
  tap is the wrong shape — the useful thing a scanner can do is make sure Morphe
  *has the sources*, after which Morphe's own UI drives the patch with you seeing
  exactly what will be applied.
- Adding a source is safer by a wide margin: Morphe validates it, asks for
  confirmation, and adding a source patches and installs nothing.

Removing it also removed a compile dependency: `@ActivityCallback` requires
`androidx.activity`, which `capacitor-android` declares `implementation` rather
than `api`, so it is absent from a consumer's compile classpath.

## Where the data comes from

Three kinds of source, all fetched as **JSON data files**. Nothing is scraped
from rendered HTML.

| Source | What it is |
|---|---|
| **Official** — `MorpheApp/morphe-patches/patches-list.json` | Machine-generated by Morphe's own release tooling. 166 patches, but only 3 packages. The only source with real `versionCodes` and signing certificates. |
| **Community** — `morphe-patches.software/data/bundles.json` | The community index's own frontend data. ~1.9 MB, 222 bundles, 964 packages. |
| **Custom** — any `<repo>/patches-list.json` or `patches-bundle.json` | Added by you. Probed before saving, so a typo fails loudly instead of creating a silently-empty source. |

> **On the community index:** it is an undocumented endpoint the site serves to
> its own browser UI, not a published API. `robots.txt` is permissive and it
> sends `Access-Control-Allow-Origin: *`, so fetching is clearly tolerated — but
> nothing contractually prevents it moving. The parser tolerates three legacy
> shapes in that file, and a future change is a one-constant fix.

### The bundled seed

`npm run build:seed` captures both live indexes, runs them through the *same*
converter the app uses at runtime, and writes `public/bundled-registry.seed` —
**463 KB gzipped** for what is 4.6 MB of JSON.

It is a **fallback, not a source**. Its bundles keep their real `sourceId` values,
which is what lets the sync logic handle it with no special casing: a successful
fetch replaces it, a failed fetch keeps it for that source only. The Sources
screen says "showing the registry bundled with the app", so staleness is visible
rather than silent.

The `.seed` extension is load-bearing: **AAPT2 decompresses any asset ending in
`.gz` at package time and strips the extension**, so shipping
`bundled-registry.json.gz` puts a 4.8 MB `bundled-registry.json` in the APK and
makes the fetch 404 — silently, because the module degrades to "no seed".

### Registry traffic goes through native HTTP

Conditional GETs need `If-None-Match`, which is not a CORS-safelisted header, so
the WebView fires an `OPTIONS` preflight — and both hosts answer it with
403/405. The request never happens. PatchIt routes registry fetches through
Capacitor's native HTTP client instead, where CORS doesn't exist, and falls back
to plain `fetch` in the browser for development. Repeat syncs cost a few hundred
bytes.

## The design system

A token layer, not per-component choices. No component carries an absolute
measurement — a switch track is 52×32 because `.md-switch` says so.

**Dynamic colour**, derived rather than selected:

1. On Android 12+, the native layer reads the platform's wallpaper-derived tonal
   palettes — the actual Monet output.
2. Material Color Utilities turns that seed into all 49 colour roles for both
   schemes. `SchemeTonalSpot` is the algorithm Android itself uses.
3. Roles land on `:root` as custom properties and bridge into Tailwind via
   `@theme inline`, so a palette swap repaints without a rebuild.

Three colour styles, mirroring Morphe Manager's own settings: **Dynamic**,
**Custom** (a seed you pick), **Mono**. Plus **AMOLED black**, which forces
`background`/`surface`/`surfaceDim` to pure `#000000` and leaves the
`surfaceContainer*` ladder alone — flatten the containers too and every card
disappears into the background.

**Shape follows the spec's role mapping.** Cards, banners and dialogs all used to
wear the *extra-large* 28px corner the scale reserves for FABs:

| Role | Radius | Used by |
|---|---|---|
| extra small | 4px | inline tags |
| small | 8px | chips, badges |
| medium | 12px | cards, banners, dialogs, avatars |
| large | 16px | bottom sheets |
| extra large | 28px | FABs |
| full | 9999px | buttons, search bar |

**The launcher icon is adaptive and themed.** It ships a foreground vector, a
background token and a `<monochrome>` layer, so on Android 13+ the system recolours
it from the wallpaper palette like any other themed icon. Legacy densities are
rasterised from the same geometry.

### Contrast is measured, not eyeballed

The first version shipped unreadable text: `on-ok-container` was hand-picked
near-black against a `#1f6f45` fill — about **3:1**, fine for large text, muddy
at the body size it was used at. TypeScript cannot see colour and the build does
not care.

`on-*` colours are now **derived by WCAG contrast**, and `resolveScheme()` runs
*after* the AMOLED override, because every derived colour is measured against the
surface it will actually sit on.

There was also a subtler bug: `Card` and `Chip` took colour overrides through
`className`, which puts two background utilities on one element — and **Tailwind
resolves that by stylesheet order, not the order you wrote it.** A dark grey card
ended up carrying dark green text at ~1.2:1. Both now take the fill as a prop.

## Architecture

```
src/
├── core/            pure logic — no React, no platform
│   ├── version.ts         Android version-string comparison
│   ├── compatibility.ts   the verdict engine
│   └── morphe.ts          hand-off orchestration
├── registry/        the data pipeline
│   ├── schema.ts          types for all three JSON shapes
│   ├── normalize.ts       defensive parsers — never throws on one bad bundle
│   ├── sources.ts         source definitions + `owner/repo` resolution
│   ├── http.ts            native/browser transport, concurrency limiter
│   ├── cache.ts           IndexedDB: raw bodies + ETag, parsed snapshot, icons
│   ├── seed.ts            the bundled offline fallback
│   └── sync.ts            fetch → parse → normalise → snapshot
├── native/          the bridge
│   ├── types.ts           the TS ⇄ Kotlin contract
│   ├── plugins.ts         typed plugin handles
│   └── web.ts             browser implementations, for fast iteration
├── theme/           Material You 3 engine (palettes + WCAG contrast)
├── state/           one store; memo boundaries between the expensive steps
├── diagnostics/     ring-buffer logger + global error capture
├── ui/              M3 primitives, inline icons, navigation chrome
└── screens/         Apps · Detail · Sources · Settings · Logs

android/app/src/main/java/app/patchit/
├── MainActivity.kt        plugin registration
├── AppScannerPlugin.kt    PackageManager scan, icons, system hand-offs
├── SystemThemePlugin.kt   Monet palette + live theme-change events
└── MorpheBridgePlugin.kt  add-source deep links + Morphe discovery
```

### Decisions worth knowing

- **`versionCodes` are proof, version names are hearsay.** A published
  `arm64-v8a` versionCode matching the device is conclusive; names like
  `7.16.51` are hand-typed in bundle manifests and drift.
- **Universal patches are tracked separately.** Two bundles publish patches that
  apply to *any* app ("Change package name", "Unlock premium"). Folding them into
  the index would make every installed app look patchable, breaking the "only
  apps with patches" filter. They're surfaced in the detail sheet instead.
- **The expensive work is memoised, not the render.** `evaluateAll` is ~300 apps ×
  ~30 patches, recomputed only when the app list or registry changes.
- **One failing source never fails a sync.** A dead repo, a 404, a malformed
  bundle: each is recorded against its own source and keeps its last-known-good
  data.

## Build

### Requirements

- Node 20+
- JDK 21 (Capacitor 7 forces `VERSION_21` in its generated Gradle file)
- Android SDK: platform 35, build-tools 35

### Web

```bash
npm install
npm run dev      # browser preview with mock packages — no device needed
npm run build    # tsc -b && vite build
```

`npm run dev` runs against `src/native/web.ts`, which provides eight fake
installed packages (including deliberately too-new and too-old ones) and the real
registry pipeline. Iterating here takes milliseconds instead of a Gradle build.

### Android

```bash
npm run build:release
npx cap sync android
cd android && ./gradlew assembleDebug
```

| Command | Output |
|---|---|
| `npm run build` | **Debuggable** — source maps on, `console` kept |
| `npm run build:release` | **Shippable** — no source maps, `console` and `debugger` stripped |

The build is `NODE_ENV`-independent by construction: Vite resolves React as
`process.env.NODE_ENV || mode`, so an ambient `NODE_ENV=development` would
silently ship React's *development* build — 673 KB instead of 402 KB.

## Verification

```bash
npm run verify:registry   # the data pipeline, against the LIVE indexes
npm run verify:theme      # every colour pair, measured
npm run typecheck
```

`verify:registry` bundles the `core/` and `registry/` modules and runs them under
Node against both real endpoints — version-comparison edge cases, parsing both
documents, converting, merging a snapshot, asserting verdicts, and finally
gunzipping the shipped seed and evaluating an app from it alone:

```
222 bundles · 4123 patches · 964 distinct packages · 966-package index
YouTube experimental 93/93 · future build too-new · Chefkoch supported

Bundled seed (cold start with no network)
  463 KB gzipped -> 4.59 MB raw
  [PASS] a cold start finds a patchable app from the seed alone
```

`verify:theme` measures **2520 text/background pairs** across 7 seeds × 9 variants
× both schemes, holds every one to WCAG AA, checks the AMOLED overrides — and then
parses the two hand-written baseline blocks out of `index.css` and holds those to
the same bar, since nothing else would.

```
[PASS] every text pair clears WCAG AA (4.5:1)
[PASS] the container ladder stays above black
[PASS] dark baseline tokens clear WCAG AA  — worst: primary on surface at 9.59:1
[PASS] light baseline tokens clear WCAG AA — worst: warn on surface at 4.81:1
```

## Permissions, and why

| Permission | Why |
|---|---|
| `QUERY_ALL_PACKAGES` | The entire point of the app. Android 11 made package visibility opt-in; without it the scan sees a handful of packages. Play-policy sensitive — PatchIt has no other way to perform its single stated function, and it transmits nothing it reads. |
| `INTERNET` | Fetching the two registry indexes. |
| `REQUEST_DELETE_PACKAGES` | Required on API 26+ for the uninstall action to be permitted. |
